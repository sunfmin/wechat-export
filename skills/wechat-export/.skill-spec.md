# skill-spec — wechat-export

## name
wechat-export

## description (frontmatter shape)
Export ONE WeChat contact's complete chat history (macOS WeChat 4.x) into a single
self-contained, mobile-friendly HTML file — WeChat-style bubbles, mapped emoji, quote
boxes, all assets inlined. Covers key extraction (Frida CCCrypt hook), SQLCipher-4
decryption, and rendering. Triggers on "导出微信聊天记录", "把某人的微信聊天记录导出成
HTML/PDF", "export my WeChat chat with <person>", "WeChat chat backup to a single file".

## should_fire (must activate)
- "把我和小明的微信聊天记录从头到尾导出成一个 HTML"
- "export my complete WeChat chat history with a specific contact to a single file"
- "微信 Mac 版，怎么把某个联系人的聊天记录导出来存档"
- "I want a self-contained HTML of one WeChat conversation, bubbles and emoji like the app"
- "帮我备份微信里和某个人的所有聊天，不要整机备份"

## decoys (must NOT activate)
- "帮我在微信里给小明发条消息" (sending a message, not exporting — computer-use/other)
- "导出我的 Slack / Jira 工作记录" (mywork, different platform)
- "把这个 Markdown 转成 PDF" (generic doc conversion)
- "微信小程序开发怎么调试" (WeChat dev, unrelated)
- "恢复我误删的微信聊天记录" (recovery, not export)

## examples
- `/wechat-export 小明` → finds the contact, extracts keys, decrypts, renders
  `~/Desktop/微信聊天记录-<name>-<start>_<end>.html`.
- "导出微信号 xiaoming_demo 的完整聊天记录为单文件 HTML"
- "export WeChat conversation with wxid wxid_demo0001 as one HTML, mobile-friendly"

## needs
- macOS, Apple Silicon, WeChat for Mac 4.x logged in.
- root (sudo) — Frida needs task_for_pid; re-signing WeChat.
- uv (Python runner), frida<17, pycryptodome, zstandard.
- External tools (cloned on demand):
  - github.com/3351666087/wechat-key-macos — Frida CCCrypt key extractor (scripts/extract_key.py)
  - github.com/Z-V-I/wechat4-db-export — wxbak decrypt+export engine
- Google Chrome (only if the user also wants a PDF; HTML needs nothing).
- Bundled: scripts/export_wechat.sh (orchestrator), scripts/render_html.py (renderer),
  scripts/preflight.sh (env check / dry-run).

## functional_test
Core deliverable = the renderer. Run:
  `uv run --with -` N/A; plain: `python3 scripts/render_html.py <sample wxbak JSON> /tmp/out.html`
Success condition (all must hold):
- exit 0; /tmp/out.html exists and is a single file;
- contains `class="quote"` (quote boxes rendered);
- contains at least one mapped emoji (e.g. 🤗 from [拥抱]) when the sample has bracket emoticons;
- NO external resource refs (no `src="http`, `href="http`, external `<link>`/`<script src>`);
- the printed message count equals the number of messages in the JSON.
Fixture: `references/sample_chat.json` — a small SYNTHETIC conversation (fake names/content)
exercising plain text both sides, mapped emoticons, a quote reply, media placeholders, and a
cross-day divider. `scripts/selftest.py` renders it and checks the conditions above.
NEVER commit a real conversation as the fixture — this repo is public.

## automation
One-button orchestrator where deterministic; HARD manual stops (unavoidable):
1. sudo password (root for Frida) — GUI/askpass approval.
2. Triggering decryption — the user must open the target chat in WeChat and tap around
   (收藏/搜索/scroll) so page reads fire CCCrypt and keys get captured.
Everything else (version detect, account-dir detect, backup, re-sign, wxbak refresh/export,
render, signature restore) is automated.

## notes / known-unsolved
- Media (image/video/voice) render as text placeholders. Quote boxes work for text quotes;
  image-quote thumbnails are AES-encrypted V2 .dat (header 07 08 56 32), image key is NOT
  derivable from the DB keys — needs a separate image-key capture (future work).
- username (Msg table hash) ≠ 微信号/alias. Resolve via wxbak list / contact db.
- Safety: operate read-only on DBs, back up db_storage first, restore WeChat signature
  (remove get-task-allow) or advise reinstall when done.
